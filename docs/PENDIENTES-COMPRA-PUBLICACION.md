# Pendientes para completar la experiencia de compra

El frontend conserva las funcionalidades y contratos actuales. Estos pendientes requieren datos de la empresa o coordinación con el equipo de backend.

## Compra como invitado

El checkout actual exige una cuenta y la creación y consulta de pedidos usan una sesión autenticada. Para habilitar invitados se necesita un contrato que permita crear el pedido, pagar, recuperar el acceso al pedido y consultar sus comprobantes sin exponer pedidos ajenos. Definir también cómo se vinculará el pedido si el comprador crea una cuenta después. Mientras eso no exista, el carrito informa que se necesita iniciar sesión y conserva sus productos.

## Destinos y tarifas

La ficha muestra únicamente las tarifas y la cobertura publicadas por el servicio de entrega. El checkout bloquea la confirmación si la modalidad no tiene una tarifa válida; un costo desconocido nunca equivale a envío gratis. La empresa debe confirmar la dirección y horario de retiro y las zonas que cubre cada tarifa. Para courier nacional, acordar con backend el destino estructurado (departamento, provincia, distrito y dirección) y la cotización. La dirección actual permite incluir provincia y departamento sin cambiar el contrato existente.

## Información que debe aprobar la empresa

Confirmar teléfono, WhatsApp, correos, dirección de retiro y horarios. Aprobar las condiciones de entrega, garantías, cambios, devoluciones y cancelación, además del aviso de privacidad y el canal de reclamaciones. El plan de negocio compartido prevé publicar la política y el Libro de Reclamaciones antes del lanzamiento. Publicar los enlaces cuando existan los documentos y canales operativos; no usar enlaces de ejemplo ni presentar documentos de trabajo como políticas aprobadas.

Estas correcciones visuales no acreditan cobros reales ni habilitación tributaria. Los estados de pago y de comprobante deben seguir mostrando el resultado informado por los servicios correspondientes.
